# Brief: production follows main, deployed by CI

## Objective

Every push to `main` whose CI checks pass publishes to
https://product-ops-base.vercel.app with nobody running a command, and a copy
with no Vercel token skips the deploy saying why.

> SOURCE: Ian Rueff, 2026-10-09, question UI — "CI despliega tras el push"

## Differentiator

Today production moves only when somebody runs `vercel deploy --prod` by hand,
and neither GUIDE.md nor CLAUDE.md asks for it, so the next merge leaves the
site behind `main` in silence. Vercel's Git integration would do it, but a
Hobby team cannot deploy a private organisation repository.

> SOURCE: the agent, 2026-10-09 — `grep -i vercel GUIDE.md CLAUDE.md`;
> https://vercel.com/docs/deployments/troubleshoot-project-collaboration

## Context and rules

- [ci.yml](../.github/workflows/ci.yml) runs `check` on push and PR to `main`
  and says it gates nothing; the deploy is the first thing it will gate.
- The CLI builds remotely with `vercel.json`'s `buildCommand`
  ([the vercel-deploy brief](2026-10-09-vercel-deploy.md)), so the job only
  uploads.
- The org and project ids from `.vercel/project.json` go in as secrets with the
  token, so a copy inherits none of Ian's project.
- `feat/template-hardening` edits `checks.md` and `gate.mjs` in other lines,
  and not `ci.yml`.

> SOURCE: the agent, 2026-10-09 — `git diff main...feat/template-hardening --stat`

## Dependencies

A Vercel token on the `ianrueff-1995s-projects` scope, which Ian creates and
stores as `VERCEL_TOKEN`: a credential, so the agent prints the command and
never holds it. Ian is admin on the repository.

> SOURCE: the agent, 2026-10-09 — `gh api repos/studiohakuna/product-ops-base`

## Scope

In: a `deploy` job in `ci.yml`, after `check`, on push to `main` only, with a
skip line naming the three secrets when the token is absent; the CI and deploy
rows of `checks.md`, and the `ci.yml` and `gate.mjs` headers, saying where the
deploy runs and what a red step leaves live.

Out: previews per branch, which stay protected and manual; a public repository;
a custom domain; any change to the five checks.

> SOURCE: Ian Rueff, 2026-10-09, question UI — CI, over a manual step, a public
> repository or nothing; Go + worktree

## Tasks

1. The `deploy` job in `ci.yml`, on Vercel CLI 54.14.5, skipping with a printed
   reason when `VERCEL_TOKEN` is empty; its header says what it now gates.
2. The CI and deploy rows of `checks.md` and the `gate.mjs` header: the deploy
   runs after the push, and a red step leaves the last green build live.
3. End checks, merge, gate, push on Ian's confirmation; that run proves the
   skip. Ian sets the token, the agent the two ids; the job is rerun.

> SOURCE: the agent, 2026-10-09

## Autonomy

Checkpoints, rung `default`, effort `high`: a CI job and three sentences, its
fork already decided. Not `repair`: this adds behaviour rather than restoring
it. It stops for Ian at the token and before the push.

> SOURCE: the agent, 2026-10-09
